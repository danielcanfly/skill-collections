# Pedagogy Protocol

## Principle

The goal is not to make content simpler than the subject. The goal is to create a staircase into the real depth.

## 1. Prior-knowledge bridge

Before a difficult concept:

- activate the prerequisite
- remind the reader where this sits in the global map
- define only the minimum new vocabulary needed

Avoid circular definitions using equally unfamiliar terms.

## 2. Layered terminology

Use three layers:

- Core: first-read essential terms
- Working: needed once the reader enters the lesson
- Reference: advanced / interview / implementation vocabulary

First appearance pattern:

**中文或 plain-language meaning → English term → one-sentence mental model → role in system/domain**

## 3. Core Path / Deep Path

Core Path must be independently understandable.

Deep Path may contain:

- derivations
- edge cases
- advanced implementation
- additional research
- exceptions
- specialized vocabulary

Do not bury essential prerequisites in Deep Path.

## 4. Worked examples and guidance fading

For novices, use worked examples before independent problem solving.

Recommended progression:

1. Fully worked example
2. Completion example with missing steps
3. Guided practice
4. Independent practice
5. Transfer problem

Do not keep full scaffolding forever. As expertise increases, fade guidance.

## 5. Retrieval practice

Use short retrieval opportunities after meaningful chunks:

- explain without looking
- distinguish A vs B
- reconstruct a process
- identify failure cause
- calculate from memory

Avoid turning every paragraph into a quiz. Retrieval should target important knowledge and require real recall.

## 6. Self-explanation

Use selectively:

- Why does this step follow?
- Which assumption makes this valid?
- Why is the wrong answer tempting?
- Explain this diagram in your own words.

Do not assume self-explanation helps every task equally. Use it where reasoning relationships matter.

## 7. Misconception repair

For high-confusion concepts, create:

- Correct model
- Common wrong model
- Why it is tempting
- Contrast example
- Quick diagnostic question

This is stronger than adding another definition.

## 8. Cognitive-load control

Watch for:

- too many new terms in one paragraph
- prerequisite concepts introduced too late
- table with too many dimensions
- diagram labels not explained
- long examples before the reader understands the goal
- redundant prose that repeats the same representation without adding information

Split, bridge, or layer instead of deleting depth.

## 9. Multiple representations

Use representation that matches the knowledge:

- process: flow diagram
- architecture: system map
- contrast: table
- timeline: chronology
- formula: worked derivation
- causal mechanism: chain / graph
- spatial relationship: diagram
- abstract concept: example + counterexample

Do not create decorative visuals that do not reduce comprehension cost.

## 10. Spiral reinforcement without recap bloat

Later lessons may reuse earlier concepts in new contexts. Prefer application-based reinforcement over repeating the same paragraph.

## 11. Transfer

A learner should eventually answer a question that is not a paraphrase of the textbook.

Transfer prompts should change at least one of:

- context
- data
- constraints
- stakeholder
- failure mode
- implementation

## 12. Learner Friction Log

If the user interacts during teaching, record:

- concept
- confusion
- failed explanation
- successful explanation
- misconception
- textbook action

Use real friction to improve the final textbook.
