# Visuals & Accessibility

## Visual Decision Gate

Create a visual only when it reduces comprehension cost.

High-value visual targets:

- architecture
- process flow
- causal chain
- timeline
- comparison
- quantitative relationship
- layered system
- decision tree
- spatial relationship

Do not add decorative images merely to make the textbook look designed.

## Visual quality

A useful diagram should:

- have one main teaching purpose
- use labels already introduced in text
- avoid unexplained abbreviations
- show direction / hierarchy clearly
- not require tiny text
- be readable in grayscale where possible

## Multiple representations

For difficult concepts, consider a combination of:

- prose
- table
- diagram
- worked example
- analogy

Do not duplicate the same information four times without adding a new perspective.

## Accessibility basics

For generated documents:

- use real heading hierarchy
- sufficient font size
- meaningful table headers
- avoid color-only distinctions
- provide textual explanation for key diagrams
- avoid images containing essential unreadable text
- keep link / citation labels meaningful
- preserve selectable text when possible

## Cognitive accessibility

Accessibility also means reducing unnecessary interpretation effort:

- explain symbols
- define abbreviations
- keep terminology consistent
- separate Core and Deep paths
- avoid giant unbroken paragraphs
